Executive Summary

Nigeria does not lack digital repositories for academic research. Current national initiatives such as TETFund's TERAS and the NgREN Institutional Repository and Information Service (NIRIS) already address important problems of research storage, discovery, preservation and institutional access.

Current National Infrastructure

  • TERAS - Federated repositories, thesis submission, institutional identity services, EagleScan similarity checking
  • NIRIS - Visibility, accessibility, preservation, federated discovery of Nigerian scholarly outputs

Core Finding

RIPATS should not replace TERAS, NIRIS, institutional repositories, plagiarism-checking systems or formal intellectual-property processes.

It should operate as a secure research-lifecycle layer around them:

Protect → Verify → Control → Track → Connect

The Problem We Solve

Research repositories can contain unpublished findings, designs, datasets, source code and intellectual-property-sensitive material. A 2023 study of Nigerian university institutional repositories identified:

  • Malware/malicious code threats
  • Password attacks
  • IP theft among prominent reported risks

Assessment of the Existing Nigerian Research Ecosystem

1.1 Existing Capabilities

System / Layer Documented Capability RIPATS Implication

1.2 Material Gaps

🔒 Confidentiality Before Publication

Unpublished designs, datasets, code and inventions may require restricted handling.

RIPATS Response: Classification + controlled disclosure

✓ Provenance

A repository record may not provide a complete security history.

RIPATS Response: Research ID + timestamp + version history + cryptographic fingerprint

🛡️ Integrity

A research file may need evidence that a registered version has not been altered.

RIPATS Response: SHA-256 verification + version comparison

🔑 Fine-Grained Authorization

Authentication does not automatically justify access to every project.

RIPATS Response: Resource-level authorization, least privilege, deny-by-default

📊 Access Accountability

Without detailed security logs, suspicious access may be hard to reconstruct.

RIPATS Response: Audit trail and security monitoring

💡 Controlled Innovation Discovery

Collaborators need enough information to discover an innovation without receiving the full research package.

RIPATS Response: Public innovation profile + access-request workflow

The Central Gap

Research security, provenance, controlled access, monitoring and safe innovation discovery should operate as one lifecycle rather than isolated functions.

RIPATS: Proposed Secure Research-Lifecycle Model

2.1 Solution Definition

RIPATS is a cybersecurity-focused research lifecycle platform that protects university research through:

  • Verified provenance
  • Controlled access
  • Integrity monitoring
  • Audit tracking

While enabling safe discovery and collaboration around promising innovations.

2.2 Operating Model

1. Register

Researcher submits project metadata and files. Security control: Verified identity and affiliation.

2. Verify

Supervisor/institution confirms relationship and authority. Security control: Role-based approval.

3. Protect - Classify

Public, Restricted, Confidential or IP-sensitive. Security control: Classification-driven policy.

4. Fingerprint

Record Research ID, version, timestamp and SHA-256 hash. Security control: Integrity evidence.

5. Discover

Expose safe innovation profile: problem, abstract, field, application, stage. Security control: No automatic exposure of restricted files.

6. Request

External user requests protected access and states purpose. Security control: Explicit access request.

7. Approve

Authorized party approves, rejects or limits access. Security control: Least privilege; time-limited permissions.

8. Monitor

Record viewing, download, sharing and permission events. Security control: Audit trail.

9. Detect

Identify unusual access or repeated failures. Security control: Rules/anomaly alerts.

10. Connect

Approved parties collaborate through institutional/IP processes. Security control: Traceable hand-off.

2.3 Roles

Researcher/Student

Creates research records, submits versions and manages permitted sharing.

Supervisor

Verifies academic relationship and participates in approvals.

University/IP Officer

Handles institutional ownership, disclosure and IP-sensitive decisions.

Investor/Industry Partner

Discovers approved innovation summaries and requests controlled access.

Security Officer

Reviews security events and alerts.

System Administrator

Manages configuration without unnecessary access to research content.

2.4 Research Classification Levels

PUBLIC

Typical content: Approved abstract, published work, non-sensitive innovation summary.

Default exposure: Discoverable.

RESTRICTED

Typical content: Full academic work or supporting material requiring controlled access.

Default exposure: Authorized users only.

CONFIDENTIAL

Typical content: Unpublished results, sensitive datasets, proprietary designs or source code.

Default exposure: Explicit approval.

IP-SENSITIVE

Typical content: Potential patent/commercial material before formal disclosure.

Default exposure: Highest control; institutional/IP review.

Security Architecture and MVP Requirements

3.1 Security Requirements

Based on OWASP guidelines for authentication, authorization, logging, and secure application development.

Layer Minimum Implementation Purpose
Authentication Strong passwords; verified institutional/email identity; OTP/MFA for sensitive actions; secure sessions Reduce account compromise
Authorization RBAC + resource-level permissions; server-side checks; deny-by-default; least privilege Prevent unauthorized access
Encryption TLS in transit; encrypted storage for sensitive documents and secrets Protect confidentiality
Integrity SHA-256 fingerprint for every registered file/version Detect unauthorized modification
Audit Logging Record who, what, resource, timestamp, result and relevant context Accountability and investigation
Monitoring Rules for failed logins, unusual downloads, abnormal project access and privilege changes Detect suspicious behaviour
File Security Type/size validation, safe storage names, malware scanning, controlled downloads Reduce malicious file risk
Backup/Recovery Versioned encrypted backups and recovery testing Preserve availability and evidence
Privacy Data minimization, purpose limitation, access control and retention rules Responsible personal-data handling

3.2 Threat Model

Threat Impact Primary Control
Compromised student account Restricted research is read/downloaded MFA/OTP, rate limits, anomaly detection
Insider privilege abuse User accesses unrelated projects Least privilege, resource authorization, audit trail
Direct API manipulation UI restrictions are bypassed Server-side authorization on every protected action
Malicious upload Server/user exposed to malicious content Validation, scanning, isolated storage
Document alteration Integrity/provenance dispute Hash, versions, controlled replacement
Audit-log tampering Incident cannot be reconstructed Restricted access, tamper detection, protected storage
Excessive external access Sensitive research exposed beyond intended scope Time-limited permission explicit approval

3.3 Three-Week MVP

MVP should demonstrate security behaviour rather than attempt every future capability.

Six Visible Modules

  • Secure login
  • Research registration/classification
  • Innovation discovery
  • Access-request/approval
  • Hash-based integrity verification
  • Security/audit dashboard

Recommended Demo Scenario

Student uploads project → RIPATS creates Research ID, timestamp hash → full document is Confidential → external user sees only innovation summary → access is requested → researcher approves time-limited access → access is recorded → abnormal access pattern is simulated → dashboard raises alert preserves audit trail.

Project Conclusion

The strongest evidence-based case for ATBU RIPATS is not that Nigerian research has no digital home.

It is that research security and research commercialization require controls that sit across the lifecycle.

Existing national infrastructure materially improved discovery, repository federation, identity and academic originality checking.

RIPATS addresses a complementary security problem: establishing trusted provenance, protecting sensitive research, enforcing controlled access, monitoring use, detecting abnormal behaviour, and exposing innovation safely.

Protect → Verify → Control → Track → Connect
